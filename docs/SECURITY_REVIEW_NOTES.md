## Manual Adversarial Review Summary

### Architecture

- **Language:** Zig (0.15.2)
- **Paradigm:** Zero-dependency (pure Zig stdlib); single external dep (`json`) for serialization
- **Entrypoints:** `src/root.zig` (public API), `src/generator.zig` (core logic)
- **Auth boundaries:** None (pure library)
- **External integrations:** OS network stack (ioctl/getifaddrs/GetAdaptersAddresses for MAC)
- **Persistence:** Optional `saveState`/`loadState` file I/O
- **Concurrency:** Mutex-protected Generator state

### Memory Safety Assessment

Zig's Debug and ReleaseSafe modes provide runtime checks for:

- Integer overflow
- Out-of-bounds slice access
- Null pointer dereference
- `@intCast` range violations

**CI tests run in both Debug and ReleaseFast modes** — this is good practice. ReleaseFast disables safety checks, but the test suite is run against both, catching divergences.

**No `undefined` memory reads detected** (all UUID byte arrays are written before read).

**Key safe patterns observed:**

- `@memcpy` used correctly with fixed-size buffers
- `@intCast` used after explicit range guards in most places
- `std.mem.readInt`/`writeInt` with explicit endianness
- Stack allocation preferred over heap (no allocator in core UUID generation)

### Cryptographic Assessment

| Component | Algorithm | Assessment |
| --------- | --------- | ---------- |
| V4 randomness | `std.crypto.random` (OS CSPRNG) | Secure |
| V7 randomness | `std.crypto.random` | Secure |
| V1/V6 clock_seq | `std.crypto.random` | Secure |
| V1/V6 node ID (default) | `std.crypto.random` | Secure |
| V3 hash | MD5 | Broken (CWE-327) |
| V5 hash | SHA-1 | Weakened (CWE-327) |
| HashContext | Wyhash(seed=0) | HashDoS risk (CWE-330) |
| SecureHashContext | Wyhash(random seed) | Secure |

### CI/CD Security Assessment

- Zig toolchain installed via unverified `curl` download (HIGH risk)
- Docker images unpinned (MEDIUM risk)
- External CI components pinned by version tag, not commit digest (MEDIUM risk)
- No SAST rules specific to Zig (gap — semgrep lacks Zig rules)
- No fuzz testing job in CI (MEDIUM gap)
- SBOM generation present — good practice

### Platform Code Assessment

| Platform | Implementation | Key Risks |
| -------- | -------------- | --------- |
| Linux | `ioctl(SIOCGIFCONF)` + `SIOCGIFHWADDR` | Fixed 64-interface buffer (INFO) |
| macOS | `getifaddrs` + `sockaddr_dl` cast | Correctly guarded by `sdl_len` |
| Windows | `GetAdaptersAddresses` | `ERROR_BUFFER_OVERFLOW` not retried (LOW) |

All three platforms correctly skip loopback interfaces and validate zero MACs.

### New Findings (Cycle 3)

Two new findings identified not covered by Cycles 1 or 2:

1. **SEC-R3-01** (Low, CWE-61): `saveState` `.tmp` file creation follows symlinks.
   `createFileAbsolute` uses `open(O_CREAT|O_WRONLY|O_TRUNC)` without `O_NOFOLLOW`/`O_EXCL`.
   A local attacker with write access to the state directory could pre-place a symlink at
   `<path>.tmp` to redirect the write. Requires local filesystem access (low likelihood).
   GitLab: [#56](https://gitlab.com/devnw/zig/uuid/-/work_items/56)

2. **SEC-R3-02** (Info, CWE-377): Five state-file tests use hardcoded `/tmp/uuid_*` paths.
   Predictable names could allow pre-seeding on shared CI runners.
   Fix: use `std.testing.tmpDir()` for isolated per-test temporary directories.
   GitLab: [#57](https://gitlab.com/devnw/zig/uuid/-/work_items/57)

### False Positive Notes (Cycle 3)

- **V7 @intCast overflow (292 million year AD):** `@intCast(i128 -> i64)` after dividing nanoseconds by 1_000_000 would only overflow at astronomical timestamps. Not a practical risk.
- **`loadState` negative-timestamp @intCast:** Same analysis — overflow only at year −292 million. Not a practical risk.
- **Empty truncation-detection block in linux.zig:** Intentional — code continues searching returned interfaces and falls back gracefully. Not dead code in the semantic sense.
